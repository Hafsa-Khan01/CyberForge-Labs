# Network Intrusion Detection with Snort

**Platform:** Ubuntu VM  
**Tool:** Snort IDS  
**Configuration:** Snort main configuration and local rules

## Objective
Configure local Snort signatures for selected ICMP and TCP traffic, then review alert output generated by controlled lab traffic.

## Network preparation
Identify the active interface and address before starting the sensor:

```bash
ip -br addr
ip route
```

Set `HOME_NET` to the monitored lab subnet and define `EXTERNAL_NET` relative to the lab topology. Select an interface that can observe the traffic between the authorized test hosts.

## Local detection rules
The accompanying [local-week3.rules](../Snort-Rules/local-week3.rules) file contains four local rules:

| SID | Detection purpose | Interpretation |
|---|---|---|
| 1000001 | ICMP traffic directed to HOME_NET | ICMP visibility; not a verdict of hostile intent. |
| 1000002 | TCP traffic to destination port 22 | SSH-destined traffic; does not prove authentication succeeded. |
| 1000003 | TCP traffic to destination port 80 | HTTP-destined traffic; does not prove an exploit. |
| 1000004 | Thresholded TCP SYN activity | Scan-like behavior indicator; not unique to Nmap. |

## Configuration validation and monitoring
The following commands are examples; adjust the interface and configuration path to the installed Snort version and local setup:

```bash
sudo snort -T -i <interface> -c /etc/snort/snort.conf
sudo snort -A console -q -c /etc/snort/snort.conf -i <interface>
```

Generate test traffic only between systems in the authorized lab. Confirm that the local rules file is included by the active configuration before interpreting alerts.

## Rule interpretation
The SYN rule uses `flags:S` and a source-based threshold to reduce repetitive alerts. A burst of SYN packets may indicate service-discovery activity, but ordinary connection attempts and other tools can produce the same flag pattern. Review destination-port diversity, timing, source identity, network topology and corroborating endpoint telemetry.

## MITRE ATT&CK context
**T1046 — Network Service Discovery** describes discovery of services running on remote systems. The threshold rule is a heuristic detection aid for possible T1046 behavior. An alert alone does not establish tool identity, intent or compromise.
